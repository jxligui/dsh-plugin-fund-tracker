# 基金小助理（fund-tracker）设计文档

一款 DeepSeek Harness（DSH）插件：在 Web 界面右缘提供常驻悬浮入口，查看大盘指数与基金行情，维护自选与持仓，按自定义分组管理基金，跟踪每日净值与盈亏。参照养基宝类基金工具的核心功能设计。

## 1. 总体架构

```
fund-tracker/                        目录结构（按层拆分，便于迭代）
├── package.json / cordis.patch.yml   bundle 清单与插件注册
├── index.js                          Host 入口：依赖注入、SQLite 生命周期、账号状态
├── lib/
│   ├── constants.js                  外部数据源 URL、指数库定义、公共常量
│   ├── store.js                      SQLite 持久层（建表、持仓 CRUD、基础库刷新、用户配置）
│   ├── market.js                     外部行情适配器（fundgz / push2 / 搜索 / 历史净值）
│   └── routes.js                     HTTP 路由处理（公开 API + 登录保护的私有 API）
├── client.js                         Client UI（单 bundle 契约，按功能区分节）

```

## 2. 数据设计

数据库 Schema 见 [schema.sql](schema.sql)，共 9 张表：

| 表 | 用途 | 说明 |
|---|---|---|
| `holdings` | 个人持仓/自选 | 主键 (account, code)，按 DSH 登录账号隔离；`watch=1` 表示在自选，与是否有份额互相独立（可同时在自选和持仓）；`pending_amount` 为待确认金额；`group_name` 为自定义分组（NULL=未分组） |
| `fund_groups` | 自定义分组 | 主键 (account, name)，`sort_order` 排序；删除分组后旗下基金变为未分组，不删除基金 |
| `fund_base` | 基金基础库 | 代码/名称/拼音简码/全拼/类型；基金每 24h 自动全量刷新（约 2.8 万条），内置指数以 kind='index' 一并写入 |
| `index_base` | 指数库 | 代码/名称/拼音/secid/分类，供指数列表与检索 |
| `etf_base` | ETF 主题库 | 内置主题 ETF 清单，行情走交易所实时价格 |
| `user_settings` | 用户设置 | 按账号存放 JSON 值（如指数显示选择） |
| `meta` | 元数据 | 基础库最后刷新时间、各账号 demo 播种标记等 |
| `fund_nav` | 基金每日净值 | 主键 (code, date)，来源 FundMNHisNetList，每只保留近 15 个净值日；打开「我的基金」时增量同步，且 Host 后台定时器每 30 分钟对全部账号持仓自动同步并结算（30 分钟节流），是持仓金额与交易结算的权威净值源 |
| `trades` | 金额制交易记录 | 加仓/减仓只记金额；`confirm_date` = T+1（QDII T+2）；确认日（含）之后的首条净值落库即折算份额并更新持仓（买入移动加权成本、卖出保持成本）；确认前的买入金额计入持仓金额 |

**基础库数据源**：`fund.eastmoney.com/js/fundcode_search.js` 全量列表（字段：代码、拼音简码、名称、类型、全拼）。插件激活时异步刷新（24 小时节流）；面板底部「基金基础库」行显示条数与上次更新时间，并提供「立即更新」按钮强制手动刷新（需登录）。

**行情数据**：指数/ETF 实时行情始终从 push2 获取、不落库；**基金每日净值落库**（fund_nav，权威计算源），由 Host 后台定时同步全库在售基金与持仓基金，避免依赖易失效的实时估值接口。

## 3. 隐私与登录门禁

- 个人数据只存在本机 DSH Profile 目录的 SQLite 文件中，不经过任何外部服务器
- 「我的基金」读写前校验 `deepseekAccount.getState()`：`status === 'credential-stored'` 视为已登录；未登录时 API 返回 403，面板锁定该标签，仅行情页可看
- 行情页为公开信息，不要求登录

## 4. 刷新策略

- 面板内「刷新间隔」下拉：15 / 30 / 60 / 120 / 300 秒，默认 60 秒，选择持久化在浏览器本地
- 打开面板立即刷新一次；后续按所选间隔轮询

## 5. 收益计算口径

- 净值主源为 `Fund_JJJZ_Data.aspx?text=<代码>`（fundgz 接口已失效，仅作兜底），带净值日与申购/赎回状态
- **持仓金额优先用服务端 `fund_nav` 表计算**：`持仓金额 = 份额 × 最新净值 + 待确认买入金额`；本地净值表为空时（首次打开）会先触发同步再计算，行情接口仅作展示兜底
- **今日净值未公布时，持有金额与持有收益改用昨日净值计算**，并在卡片上标「按昨日净值」；
  今日盈亏此时记为 0（不再用估值涨跌幅反推）
- `持有金额 = 份额 × 计算净值`
- `今日盈亏 = 持有金额 × 涨跌幅 / (100 + 涨跌幅)`（由涨跌幅反推昨日基数）
- `持有收益 = (计算净值 − 成本价) × 份额`；`收益率 = 计算净值 / 成本价 − 1`
- **加仓/减仓为金额制**：确认前卡片显示「待确认 ¥金额」且金额已计入持仓金额；确认日后自动折算份额（`份额 = 金额 ÷ 确认日净值`）
- 汇总行同时给出总资产、总今日盈亏、总收益率

## 6. 功能清单

| 模块 | 功能 |
|---|---|
| 今日行情 | 大盘指数（分页、★加自选）、全部基金（在售/全部筛选、类型与排序）、ETF 实时行情 |
| 我的自选 | 自选大盘指数（✕取消）；自选基金按持仓状态区分：持仓→加/减仓且不可取消自选，未持仓→加入持仓/取消自选 |
| 持仓基金 | 资产总览、自定义分组 tab、排序、紧凑卡片（默认显示金额/净值/成本/份额/收益率）、展开编辑、加减仓、移入分组、移除 |
| 分组管理 | 新建/改名/删除分组；未分组基金勾选后批量分配到已有分组 |
| 金额制交易 | 加/减仓只填金额按确认日净值折算份额（T+1 / QDII T+2）；取不到净值记「待确认」，后续自动折算并计入持仓金额 |
| 添加 | 本地库搜索（代码/名称/拼音简码如 `HXCZHH`）、远程搜索兜底、手动输码；金额优先 |
| 详情 | 最新净值、成立以来涨幅、六档区间涨幅、近 3 月净值走势图 |
| 批量导入 | 每行「基金代码 金额」按最新净值折算份额成本，同代码累加 |
| 净值库 | 每日净值 + 全量在售基金净值自动落库，后台定时同步，设置页显示进度 |
| Tab 布局 | 一级、二级 Tab 均可拖动排序，顺序与当前页保存在浏览器本地 |
| 安全 | 未登录锁定个人页（403）；数据本地 SQLite 持久化 |

## 7. 自测机制（专家模式）

`test/` 目录包含一套无需启动 DSH 的自测层：

- `test/harness-mock.mjs` — 模拟宿主契约（`webServer.register` 必须带 `kind` 字段等），契约错误在测试期即失败
- `test/routes.test.mjs` — 17 个 API 集成测试：注册、debug 自诊断、会话、指数/基金分页、拼音检索、持仓增删改查、金额制交易结算、自定义分组增删改移/批量、用户设置、行情适配器（真实网络可选）

运行方式（Node ≥ 22，自带 node:sqlite 与 test runner）：

```
node --test test/routes.test.mjs
```

注意：测试通过 `lib/store.js` 直接打开真实的 `~/.dsh/fund-tracker/fund-tracker.db`（`FT_TEST_PROFILE` / `DSH_PROFILE_DIR` 均不生效），因此首次运行前需先确保基础库已填充（约 2.8 万条基金、29 条指数）；行情相关用例会访问东方财富真实接口，无网络时仍会执行但只断言返回结构。

规则：任何 Host 端改动必须先通过全部测试再安装（install_bundle）。

## 8. 已知边界

- fundgz 估值为盘中估算（约 1 分钟更新），收盘后回退到最新披露净值；ETF 可后续切换 push2 实时价格
- 部分场内 ETF 无盘中估值，涨跌显示「—」
- 免责：数据仅供参考，不构成投资建议
